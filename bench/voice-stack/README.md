# Local voice-stack benchmark

Answers one question: **can a fully local STT + TTS voice stack round-trip under
~1.5s on this 2014 Haswell box (i7-4790, 4 cores, AVX2, no AVX-512) while workers
are busy?** See [RESULTS.md](RESULTS.md) for the measured numbers and the verdict.

No Discord, no API, nothing leaves the box. This branch only measures.

## Run it

```bash
./setup.sh   # once: fetch models (~450MB) + build whisper.cpp + uv sync
./run.sh      # idle pass + loaded pass, then writes RESULTS.md
```

`run.sh` is the single command that produces the report.

## What it measures

- **TTS** — hexgrad/Kokoro-82M (ONNX Runtime, CPU): time-to-first-audio and
  realtime factor for a ~15-word reply and a ~60-word reply.
- **STT** — whisper.cpp `base.en`: transcription latency for 3s / 5s / 10s
  utterances (fixtures synthesized by `make_fixtures.py`).
- Peak RSS per model.
- End-to-end round trip: audio stops → transcript → assumed 2s model turn (the
  real model is **not** called) → first audio out.

Every number is captured **twice**: idle, and under load (2 numpy busy-spin
processes pinned to physical cores with `taskset`, saturating 2 of 4 cores).
Each case is the median of 3 timed runs after a discarded warmup.

## Files

| File | Role |
|---|---|
| `run.sh` | one-command entrypoint (idle + loaded → RESULTS.md) |
| `setup.sh` | fetch models, build whisper.cpp, `uv sync` |
| `benchmark.py` | one measurement pass; `--load N`, `--out file.json` |
| `make_fixtures.py` | synthesize the 3s/5s/10s STT input clips |
| `loadgen.py` | one CPU-pinned busy worker |
| `report.py` | render RESULTS.md from the two result JSONs |
| `results/*.json` | raw measured numbers (committed for provenance) |

Models, the whisper.cpp checkout, fixtures and the venv are git-ignored (fetched
or generated by the scripts).
